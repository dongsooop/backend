# BlindDate

## Responsibility

과팅 세션 참가자의 선택을 기록하고 상호 선택의 매칭 결과를 확정한다.

## Terminology

- Session: 참가자가 함께 과팅을 진행하는 단위.
- Choice: 참가자가 한 상대를 선택한 기록.
- Match: 두 참가자가 서로 선택한 결과.

## Main Flow

선택을 기록하고 상호 선택이면 두 참가자를 매칭 확정한 뒤 채팅방 생성 이벤트를 보낸다.
선택 시간이 종료되면 선택 접수를 닫고 미매칭 참가자만 실패 이벤트 대상으로 확정한다.

## Domain Rules

- 매칭 성공 참가자에게 실패 이벤트를 발행하지 않는다.
- 최종 실패 판정 뒤 도착한 선택은 매칭 성공으로 전환할 수 없다.
- 종료 판정을 반복해도 실패 대상을 다시 반환하지 않는다.

## Concurrency / Consistency

선택 처리와 세션 종료는 같은 이벤트 큐에서 실행한다.
참가자 저장소의 `recordChoice`와 `finalizeChoices`는 같은 모니터에서 실행해
상호 선택 기록 및 매칭 확정과 선택 접수 종료 및 실패 대상 확정을 원자적으로 처리한다.
최종 결과가 확정된 세션 ID는 전체 참가자 데이터 초기화 시 함께 제거한다.
저장소 모니터 안에서는 네트워크 호출이나 메시지 전송을 하지 않는다.

## Failure Handling

채팅방 생성 또는 이벤트 발행 오류는 로그로 남긴다. 확정한 성공 결과를 매칭 실패로 바꾸지 않는다.
이벤트 전달 재시도 및 재접속 시 결과 재전송은 현재 제공하지 않는다.

## Decisions

큐 직렬화 외에 저장소에서도 최종 결과를 확정해 선택 접수 종료와 실패 대상 조회 사이의
경쟁 조건을 막는다. 저장소 모니터는 세션 간 짧은 메모리 연산도 직렬화하지만
기존 단일 이벤트 큐와 같은 실행 제약이며 외부 채팅방 생성은 잠금 밖에서 수행한다.

## Out of Scope

일대일 채팅방 저장과 일반 채팅 메시지 처리는 Chat 도메인의 책임이다.
