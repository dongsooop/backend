# Domain Documents

이 디렉터리는 동숲 백엔드의 도메인 문서를 관리합니다.

도메인 문서는 코드의 상세 구현을 그대로 설명하는 문서가 아니라, **해당 도메인이 무엇을 책임하고 왜 현재 구조를 선택했는지**를 설명하는 장기 문서입니다.

## 위치 규칙

도메인 패키지와 문서 이름을 가능한 한 동일하게 맞춥니다.

예:

- `src/main/java/com/dongsoop/dongsoop/notice/**`
  - `docs/domains/notice.md`
- `src/main/java/com/dongsoop/dongsoop/member/**`
  - `docs/domains/member.md`
- `src/main/java/com/dongsoop/dongsoop/meal/**`
  - `docs/domains/meal.md`

모든 Java 패키지가 반드시 하나의 도메인 문서를 가져야 하는 것은 아닙니다.

`common`, `date`, `s3`, `jwt`처럼 여러 도메인에서 사용하는 기술 지원 영역은 필요에 따라 `docs/architecture/` 또는 별도의 기술 문서에서 관리할 수 있습니다.

## 작성 원칙

### 1. 현재 도메인의 결정만 기록합니다

현재 문서가 소유하지 않는 결정은 상세히 복사하지 않습니다.

예:

> Notice 저장 이후 Notification 생성이 발생할 수 있습니다.  
> 발송 대상과 재시도 정책은 `notification.md`에서 결정합니다.

### 2. 용어는 Glossary를 따릅니다

공통 용어는 `../glossary.md`를 기준으로 사용합니다.

새 용어가 프로젝트 전체에서 반복될 가능성이 있다면 도메인 문서 안에만 정의하지 말고 Glossary 추가를 검토합니다.

### 3. PR보다 오래 남을 내용만 기록합니다

문서에는 현재 구현의 책임, 원리, 결정 이유, 영향과 제약을 기록합니다.

작업 중 시도했던 모든 시행착오를 시간순으로 남기지 않습니다.

### 4. 구현과 문서가 어긋나지 않게 유지합니다

도메인 규칙, 주요 처리 흐름, 저장 구조, 실패 처리, 동시성 정책 등의 의미가 바뀌었다면 관련 문서를 검토합니다.

단순 리팩터링이나 이름 변경처럼 설계 의미가 바뀌지 않는 경우 불필요하게 수정하지 않습니다.

### 5. Public 저장소에 적합한 내용만 기록합니다

Secret, Credential, 실제 사용자 데이터, 내부 운영 계정, 비공개 인프라 접근 정보는 기록하지 않습니다.

## 문서 책임

각 도메인 문서는 상단에서 다음을 명확히 합니다.

- 이 문서가 결정하는 것
- 이 문서가 결정하지 않는 것
- 다른 문서에 위임하는 결정

이 기준을 통해 동일한 정책이 여러 문서에 중복 정의되지 않도록 합니다.

## 새 문서 만들기

새 도메인 문서는 `_template.md`를 복사해 작성합니다.

처음부터 모든 항목을 채우기 위해 추측하지 않습니다.
현재 코드와 확인 가능한 결정만 작성하고, 모르는 부분은 빈 상태로 남기거나 후속 Issue로 분리합니다.
