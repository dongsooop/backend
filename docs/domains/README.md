# Domain Documents

이 디렉터리는 동숲 백엔드의 도메인 문서를 관리합니다.

이 디렉터리에는 이미 작성된 도메인 문서가 있습니다. 문서는 해당 도메인의 책임과 용어를 설명합니다.

변경의 판단 근거는 여기에 추가하지 않습니다. PR 설명에 씁니다.

## 위치 규칙

도메인 패키지와 문서 이름을 가능한 한 동일하게 맞춥니다.

예:

- `src/main/java/com/dongsoop/dongsoop/notice/**`
  - `docs/domains/notice.md`
- `src/main/java/com/dongsoop/dongsoop/member/**`
  - `docs/domains/member.md`
- `src/main/java/com/dongsoop/dongsoop/meal/**`
  - `docs/domains/meal.md`

모든 Java 패키지가 반드시 하나의 도메인 문서를 가져야 하는 것은 아닙니다.

`common`, `date`, `s3`, `jwt`처럼 여러 도메인에서 사용하는 기술 지원 영역은 기존 문서를 참조합니다. PR의 판단 근거를 남기려고 `docs/architecture/`나 별도 기술 문서를 새로 만들지 않습니다.

## 작성 원칙

### 1. 기존 문서는 자신의 결정만 담습니다

이미 있는 문서가 소유하지 않는 결정은 상세히 복사하지 않습니다. PR의 새 판단 근거는 어느 문서에도 추가하지 않고 PR 설명에 씁니다.

예:

> Notice 저장 이후 Notification 생성이 발생할 수 있습니다.  
> 발송 대상과 재시도 정책은 `notification.md`에서 결정합니다.

### 2. 용어는 소유 도메인이 정의합니다

각 도메인은 자신의 `Terminology` 섹션에서 해당 도메인이 소유한 용어를 정의합니다.

연결된 다른 도메인이 그 개념을 사용할 때는 별도의 표현을 만들지 않고 **소유 도메인의 용어를 그대로 사용합니다.**

예:

> Notice 도메인이 `Notice`를 정의했다면 Notification 도메인에서도 같은 개념을 `Announcement`로 바꾸어 부르지 않습니다.

다른 도메인의 용어 정의를 현재 문서에 다시 작성하지 않고 해당 문서를 참조합니다.

프로젝트 전반에서 여러 도메인이 함께 사용하는 공통 용어만 `../glossary.md`에 정의합니다.

### 3. PR마다 문서를 만들지 않습니다

지금은 변경의 판단 근거를 도메인 문서에 남기지 않습니다. 방식 선택, 대안, trade-off, 위험, 검증은 PR 설명에 씁니다.

이미 있는 문서는 지우지 않습니다. 그 문서가 책임과 용어를 설명하고 있으면 그 내용을 다른 이름으로 다시 정의하지 않습니다.

### 4. 판단 근거로 문서를 갱신하지 않습니다

도메인 규칙, 흐름, 용어가 바뀌면 기존 도메인 문서는 그 사실에 맞출 수 있습니다. 왜 그렇게 바꿨는지, 무엇을 기각했는지는 문서에 넣지 않고 PR 설명에 씁니다.

새 도메인 문서는 PR을 위해 만들지 않습니다.

### 5. Public 저장소에 적합한 내용만 기록합니다

Secret, Credential, 실제 사용자 데이터, 내부 운영 계정, 비공개 인프라 접근 정보는 기록하지 않습니다.

## 문서 책임

이미 있는 도메인 문서는 상단에서 다음을 구분합니다. PR마다 이 항목을 채우려고 문서를 새로 쓰지 않습니다.

- 이 문서가 결정하는 것
- 이 문서가 결정하지 않는 것
- 이 도메인이 소유한 용어
- 다른 문서에 위임하는 결정과 용어

이 기준을 통해 동일한 정책이나 용어가 여러 문서에 중복 정의되지 않도록 합니다.

## 템플릿

`_template.md`는 이미 있는 도메인 문서의 형식을 보여 줍니다. PR마다 이 템플릿을 복사해 문서를 만들지 않습니다.
