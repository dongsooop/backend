# Glossary

프로젝트 문서와 코드에서 사용하는 공통 용어의 단일 원본입니다.

## 작성 원칙

- 같은 개념에는 하나의 용어만 사용합니다.
- 코드의 타입명, 필드명, API 용어와 문서 용어가 다르면 혼동이 생기므로 가능한 한 동일한 표현을 사용합니다.
- 새로운 용어를 추가하기 전에 기존 용어와 의미가 겹치는지 확인합니다.
- 비슷한 용어는 차이를 명확히 정의합니다.
- 특정 도메인 내부에서만 쓰이는 세부 용어는 해당 도메인 문서에서 정의할 수 있습니다.
- 다른 문서에서는 여기의 정의를 다시 작성하지 않고 링크만 참조합니다.

## Terms

### Notice

학교 또는 학과에서 제공하는 공지 데이터를 의미합니다.

프로젝트 내부에서는 같은 개념을 `Announcement`, `Board Post`, `School Post` 등으로 바꾸어 부르지 않습니다.

세부 분류와 처리 규칙은 `docs/domains/notice.md`에서 결정합니다.

### Official Notice

학교 공통 공지를 의미합니다.

코드의 `NoticeType.OFFICIAL`과 동일한 개념입니다.

### Department Notice

특정 학과에 속한 공지를 의미합니다.

코드의 `NoticeType.DEPARTMENT`와 동일한 개념입니다.

### Member

서비스에 가입하고 인증 가능한 사용자 계정을 의미합니다.

`User`와 혼용하지 않고 프로젝트 도메인에서는 `Member`를 기본 용어로 사용합니다.

세부 규칙은 `docs/domains/member.md`에서 결정합니다.

### Device

서비스 알림을 수신하거나 클라이언트 설치 상태를 식별하기 위해 다루는 사용자 기기 단위를 의미합니다.

`Member`와 `Device`는 동일한 개념으로 취급하지 않습니다.

기기 식별 및 회원과의 연결 규칙은 관련 도메인 문서에서 결정합니다.

### Notification

사용자에게 실제로 전달되는 알림 또는 알림 전달 흐름을 의미합니다.

예약 정보나 사용자의 리마인드 설정 자체와는 구분합니다.

알림 대상 선정, 발송, 실패 처리 정책은 Notification 도메인 문서에서 결정합니다.

### Reminder

특정 시점에 다시 알림을 발생시키기 위한 사용자 설정 또는 예약을 의미합니다.

실제로 전송되는 `Notification`과 구분합니다.

### Subscription

사용자가 특정 범주의 정보를 지속적으로 받아보기 위해 등록한 상태를 의미합니다.

구독 대상과 적용 범위는 해당 도메인 문서에서 결정합니다.

### Crawling

외부 웹 페이지를 조회하고 필요한 데이터를 수집하는 처리 전체를 의미합니다.

HTML 파싱만을 의미하는 `Parsing`과 구분합니다.

### Parsing

가져온 원본 데이터에서 필요한 구조와 값을 추출하는 처리를 의미합니다.

외부 요청과 저장까지 포함하는 `Crawling`보다 좁은 개념입니다.

### Domain Document

`docs/domains/<domain>.md`에 위치하며, 해당 도메인의 책임과 주요 기술적 결정을 설명하는 문서를 의미합니다.

PR 설명보다 장기적으로 유지해야 하는 설계 맥락을 상세하게 기록합니다.
